# Baithul Madeena ERP — Business User Guide

## 1. About the ERP

Baithul Madeena ERP is a branch-aware real-estate operations and finance system.
It helps teams manage:

- Owners and tenants
- Properties
- Owner and tenant agreements
- Payment schedules and collections
- Receipts, vouchers, cheques and petty cash
- Quotations and invoices
- Maintenance work orders
- Vendors and inventory
- Operational dashboards and reports
- Audit history
- Zaakiy operational intelligence

The system is designed for daily operational control. Financial totals and
branch access are controlled by the backend, so users should not rely on values
typed into the browser or on another branch's records.

## 2. Signing in and branch context

1. Open the ERP URL provided by your administrator.
2. Enter your active user email and password.
3. Select a branch if the system provides more than one authorized branch.
4. Confirm the branch name shown in the application header before creating or
   reviewing records.

Normal users only see their active authorized branch. Super Admin users can
switch between authorized branches. Selecting a branch reloads branch-sensitive
data throughout the application.

There is no general All Branches mode in the normal ERP screens. Overall
Business scope is available only where it is explicitly provided, such as the
Intelligent Report for Super Admin users.

To sign out, use the user menu and choose **Logout**. Always log out on shared
computers.

## 3. Main dashboard

The Operational Dashboard provides a quick business snapshot for the active
branch:

- Owners
- Tenants
- Properties
- Current owner agreements
- Current tenant agreements
- Available properties
- Occupied properties
- Agreements expiring soon
- Tenant outstanding amounts, when authorized
- Owner payable amounts, when authorized
- Overdue tenant installments
- Pending cheques
- Open work orders

Dashboard figures are calculated by the server. A loading indicator means the
figures are not ready yet; it does not mean the value is zero.

Financial cards may be hidden for users who do not have financial viewing
permission. Hidden financial information is restricted, not an indication of
zero balance.

The Accounts Dashboard is separate. It focuses on inward and outward money,
petty cash, payment modes, receivables, payables and cheque activity.

## 4. Customers: Owners and Tenants

Owners and tenants are managed as customers. A customer can have an Owner role,
a Tenant role, or both roles.

### Create an Owner or Tenant

1. Open **Customers**.
2. Choose **Create Customer**.
3. Select the customer type: Individual or Organization.
4. Enter the name and required contact details.
5. Select the required role: Owner, Tenant, or Both.
6. Save the customer.

The customer code is generated by the system. Do not try to type a replacement
code or branch identifier into a derived field.

The customer must belong to the active branch. Customers from another branch
cannot be selected for agreements or branch-owned transactions.

## 5. Properties

A Property is the directly leasable asset managed by the ERP. Use the current
Property record for the unit or asset being leased.

### Create a property

1. Open **Properties**.
2. Choose **Create Property**.
3. Select the Owner.
4. Enter the building/property name, unit number, address and other required
   details.
5. Select a valid property type.
6. Save the property.

The property code is generated from the business inputs using this pattern:

```text
BRANCH-EMIRATE-BUILDING-UNIT-PROPERTYTYPE
```

Short codes are used for the branch, emirate and property type. The building
name is retained, spaces are replaced with hyphens, and the result is kept
readable. For example:

```text
DXB-DU-BURJ-VIEW-101-APT
```

Do not manually overwrite the generated property code. If the code is wrong,
correct the source fields and save again according to your permissions.

Properties are directly linked to Owners and agreements. Availability is based
on agreement coverage and dates, not only on the visible property status.

## 6. Owner Agreements

An Owner Agreement records the property or properties taken from an Owner by
Baithul Madeena.

### Create an Owner Agreement

1. Open **Owner Agreements**.
2. Select the Owner and property.
3. Enter the start date and end date.
4. Enter the agreed amount and payment terms.
5. Review the generated payment schedule.
6. Save the agreement.

The agreement number is generated by the system. New agreements normally start
in **Draft** status.

### Owner Agreement lifecycle

The normal lifecycle is:

```text
Draft → Pending Approval → Approved → Commenced
```

Depending on the business situation, an agreement can also be placed on hold,
resumed, extended, renewed, terminated or cancelled according to the available
actions and permissions.

After approval or commencement, important commercial fields may be locked.
Use the dedicated lifecycle actions instead of editing status directly.

Each successful lifecycle action is recorded in the agreement history and the
central audit trail.

## 7. Tenant Agreements and availability

A Tenant Agreement leases an available property to a Tenant.

### Create a Tenant Agreement

1. Open **Tenant Agreements**.
2. Select the Tenant.
3. Select the Property.
4. Select the source Owner Agreement where required.
5. Enter dates within the Owner Agreement coverage.
6. Review availability.
7. Enter payment terms and review the schedule.
8. Save the agreement.

The system rejects a Tenant Agreement when:

- The property belongs to another branch
- The property is outside the Owner Agreement coverage
- Dates overlap an existing blocking tenancy
- The selected Owner Agreement is invalid
- Required payment schedule information is missing

Date overlap protection covers exact, partial, contained and containing
overlaps. A future agreement does not automatically mean the property is
occupied today unless the business rule for that status says it reserves the
property.

### Tenant lifecycle

Use the same controlled lifecycle pattern:

```text
Draft → Pending Approval → Approved → Commenced
```

Use the dedicated actions for hold, resume, extension, renewal, termination
and cancellation. Do not change lifecycle status through ordinary editing.

## 8. Payments and payment lines

Payment schedules appear inside agreement, invoice and work-order screens.
Each payment line shows its amount, due state, paid amount and outstanding
amount where applicable.

### Payment modes

The supported payment modes are:

- Cash
- Cheque
- Bank Transfer

Select the payment mode before entering its additional details. When the mode
changes, old mode-specific values are cleared.

### Cash payment

1. Select **Cash**.
2. Enter the payment date and amount.
3. Review the installment allocation.
4. Submit the payment.

If the remarks field is blank, the system creates a standard cash payment
remark. The system generates the inward or outward document number.

### Cheque payment

1. Select **Cheque**.
2. Enter cheque number.
3. Enter cheque date.
4. Enter bank name where required.
5. Submit the payment.

New cheques start as **Received**. Authorized Accounts users can move a cheque
through the controlled lifecycle:

```text
Received → Deposited → Cleared
                     ↘ Bounced
Received/Deposited → Cancelled
```

Invalid transitions, such as Received directly to Cleared, are rejected. A
cheque action updates the same financial transaction; it does not create a
duplicate payment.

### Bank transfer payment

1. Select **Bank Transfer**.
2. Enter the bank reference.
3. Enter the transfer date.
4. Submit the payment.

Required bank details must be provided before the payment can be posted.

### Partial and full payments

A partial payment reduces the outstanding amount while leaving the line open.
When the remaining balance is settled, the line becomes paid.

The system rejects payments greater than the outstanding balance. Never use a
manual paid or outstanding amount to force a balance.

### Receipt links

When a payment line is paid, a receipt link is available beside the payment
record where supported. Select the link to open or download the receipt. The
receipt remains connected to the original financial transaction.

### Duplicate submission protection

The system protects payment forms against double submission. After selecting
Submit, wait for the result before clicking again. If a request is repeated,
the same idempotency protection prevents a second financial transaction.

## 9. Voiding a financial transaction

Voiding is restricted to users with `accounts.void` permission.

1. Open the transaction.
2. Choose **Void**.
3. Enter a clear reason.
4. Confirm the action.

The original document and transaction history are preserved. The financial
effect is reversed according to the system rules, and the installment balance
is restored where applicable.

A transaction cannot normally be voided twice. Voiding is branch-scoped and
cannot be used on another branch's transaction.

## 10. Accounts

The Accounts area includes:

- Inward transactions and receipts
- Outward transactions and vouchers
- Payment mode filtering
- Cheque status filtering
- Pending cheque discovery
- Petty cash daybook
- Cash movement reports
- Accounts dashboard

Financial actions require the appropriate permissions:

```text
accounts.view  — view financial information
accounts.post  — post payments and cheque actions
accounts.void  — void posted transactions
```

The system derives transaction direction from the business operation. For
example, tenant collections are inward and owner payments are outward.

## 11. Petty Cash

Petty Cash records small operational cash movements.

### Cash in

1. Open **Accounts → Petty Cash**.
2. Select Cash In.
3. Enter the amount and particulars.
4. Submit the entry.

### Cash out

1. Select Cash Out.
2. Enter the amount and particulars.
3. Submit the entry.

Running balances are calculated by the backend. Users cannot type an opening,
closing or running balance to override the daybook. Zero and negative amounts
are rejected where not allowed.

## 12. Billing

The Billing area contains:

- Quotations
- Invoices
- Payment lines
- Payment status updates
- Receipt/payment metadata

### Quotation

1. Open **Billing → Quotations**.
2. Create the quotation and enter its line items.
3. Save and update it as permitted.
4. Convert it to an invoice when the business process requires it.

### Invoice

1. Open **Billing → Invoices**.
2. Create the invoice and line items.
3. Review the amount and due date.
4. Add payments using cash, cheque or bank transfer as appropriate.

Invoice payments create the related financial record and preserve payment
metadata. Invoice and quotation records remain branch-scoped.

## 13. Maintenance and Work Orders

The Maintenance area manages vendors, inventory and work orders.

### Create a Work Order

1. Open **Maintenance → Work Orders**.
2. Select the property.
3. Enter the problem/request details.
4. Select priority and status.
5. Assign a vendor when required.
6. Add parts or inventory items where applicable.
7. Save the work order.

Work orders support controlled statuses such as Draft, Open, Assigned, In
Progress, Completed and Cancelled, subject to the available actions.

Work-order payments preserve payment mode and cheque/bank metadata. They use
the same financial posting and duplicate-submission protections as other
payments.

Inventory consumed by a work order must be recorded through stock movement.
Do not treat a manually edited stock figure as a stock transaction.

## 14. Reports

Open **Reports** to access the reporting area. Report filters are applied on
the server and totals include the full filtered result, not only the visible
page.

Available reports include:

- Owner Agreement Report
- Tenant Agreement Report
- Agreement Expiry Report
- Tenant Outstanding Report
- Owner Payable Report
- Inward Receipt Report
- Outward Voucher Report
- Daily Cash Movement Report
- Petty Cash Report
- Intelligent Report

Use date ranges, status, customer, property, payment mode, cheque status and
search filters where provided. Large reports use pagination.

Financial reports require Accounts viewing permission. Reports respect the
active branch and do not expose another branch by changing a URL or filter.

## 15. Intelligent Report

The Intelligent Report is a management report, not a statutory accounting
Profit and Loss statement.

It combines verified ERP data for the selected period and can include:

- Operational Profit/Loss
- Operating margin
- Operating income and cost
- Total inward and outward movement
- Net cash movement
- Collection efficiency
- Tenant receivables
- Owner payables
- Overdue installments
- Pending and bounced cheques
- Occupied and available properties
- Occupancy percentage
- Expiring agreements
- Maintenance and petty cash costs
- Deterministic leakage findings
- Trend charts
- Branch comparison for Super Admin Overall Business scope

### Periods

Use:

- This month
- Last month
- Last 3 months
- Last 6 months
- Last 12 months
- This year
- Custom date range

### Scope

Normal branch users receive their active branch only. Super Admin can choose:

- Selected branch
- Overall Business

Overall Business must be selected explicitly and is not a general data access
mode for other screens.

### Important accounting note

The report uses records captured in Baithul Madeena. Operational Profit/Loss is
an ERP management metric and is not a statutory or general-ledger Profit and
Loss statement.

### Export and Zaakiy analysis

- **Export PDF** creates a branded report using the same backend values shown
  on screen.
- **Zaakiy Analysis** explains verified trends and findings. It is advisory and
  cannot post payments, change agreements or modify records.
- If Zaakiy is unavailable, the verified report metrics remain available.

## 16. Audit Trail

The Audit Trail records important successful actions, including:

- Customer and property creation or updates
- Agreement lifecycle changes
- Payments and voids
- Cheque transitions
- User access changes
- Work-order actions
- Billing actions

Audit entries show the actor, branch, action, affected record, before/after
values and business metadata where applicable.

Audit records are append-only for normal users. The Audit Trail is available
only to users with `audit.view` permission and is branch-scoped.

Use the Audit Trail to answer:

- Who performed the action?
- What changed?
- When did it happen?
- Which branch and record were affected?

## 17. Zaakiy assistant

Zaakiy is the read-only operational intelligence assistant created by **Zv3 —
ZaakiyV3RSE** for Baithul Madeena ERP.

Open Zaakiy from the top navigation or the Zaakiy page. Ask questions in
normal business language, for example:

- What is today's inward collection?
- Which agreements expire in the next 30 days?
- Which tenant agreements still have outstanding amounts?
- Which properties are available now?
- Show open maintenance work orders.
- How many pending cheques do we have?
- Show bounced cheques this month.
- Which owners are due payments this week?
- Summarize this tenant's agreements and balance.
- What is the recent activity for agreement TA-XXXX?

Zaakiy can combine authorized read skills for questions involving agreements,
accounts, properties, customers, maintenance, reports, billing, dashboards and
audit activity.

Zaakiy:

- Uses the current active branch
- Checks user permissions before retrieving data
- Uses backend-calculated totals
- Answers from verified ERP evidence
- Provides safe links to relevant ERP pages where available
- Can explain trends and management findings
- Does not post payments or alter ERP records

Zaakiy does not replace the source screens. Always open the linked record or
report when a financial or operational decision requires verification.

## 19. Permissions and common access messages

The application may hide a menu item or reject an action when the user lacks
permission. Typical permissions include:

```text
accounts.view  — view financial information
accounts.post  — post payments and cheque actions
accounts.void  — void posted transactions
audit.view     — view the Audit Trail
```

Frontend buttons are only a convenience. The backend remains the final access
control. A user must have both the permission and access to the active branch.

If a record is not visible:

1. Confirm the selected branch.
2. Confirm the record belongs to that branch.
3. Confirm your user permission.
4. Refresh the page and try again.
5. Contact a Branch Admin or Super Admin if access is still required.

## 20. Loading, empty and error states

- **Loading:** The system is retrieving data. Wait for the result.
- **Empty:** The filters are valid but no matching records exist.
- **Restricted:** The information requires a permission you do not have.
- **Error:** The request failed. Use Retry, refresh, and report the request ID
  to an administrator if the issue continues.

Do not interpret a loading or restricted screen as zero business activity.

## 21. Good operating practice

- Confirm the active branch before creating records.
- Use generated codes and document numbers; do not invent replacements.
- Review payment mode details before submitting.
- Never click Submit repeatedly when a payment is processing.
- Record clear reasons for voids, holds, extensions and terminations.
- Use dedicated lifecycle actions instead of editing status fields.
- Reconcile reports with source records when making financial decisions.
- Use Audit Trail for sensitive changes.
- Log out on shared devices.
- Never share passwords, API keys, session cookies or private links.

## 22. Quick daily checklist

1. Sign in and confirm the active branch.
2. Review Dashboard alerts and expiring agreements.
3. Review pending cheques and overdue balances if authorized.
4. Process new owners, tenants, properties and agreements.
5. Record payments with the correct mode and metadata.
6. Review open maintenance work orders.
7. Check receipts and vouchers after financial posting.
8. Review Reports or the Intelligent Report for management follow-up.
9. Check Audit Trail for sensitive or unusual actions.
10. Log out when finished.

## 23. Support information to provide

When reporting an issue, provide:

- Your username
- Active branch
- Page or feature name
- Record number or code
- Approximate time of the issue
- What action you attempted
- The visible error message
- Request ID, if shown

Never send passwords, API keys, session cookies or the contents of the server
`.env` file.

## 24. Accounting and system limitations

Baithul Madeena is an operational ERP. The following items remain outside the
current business-user scope or may be future enhancements:

- Full statutory General Ledger accounting
- Automatic All Branches mode across every ERP screen
- Advanced report export formats beyond the available PDF/report features
- Complex cheque reversal/accounting policy for bounced cheques
- Scheduled report delivery and email automation
- Procurement and advanced inventory workflows where not enabled
- Attachments and notification modules where not enabled

The application should always be treated as the source for the records and
calculations it captures. Consult the responsible finance or management team
for statutory accounting decisions.
